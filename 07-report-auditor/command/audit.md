# 보고서 숫자 감사 — 원본 대조부터 검토의견까지

대상: **$ARGUMENTS**
(비어 있으면 가장 최근에 만든 보고서 `.md` 를 찾아 **사용자에게 확인받고** 진행한다)

아래를 순서대로 수행한다. **한 단계씩 결과를 보고하고 다음으로 간다.**

---

## 1. 무엇을 대조할지 먼저 정한다

보고서를 **읽지 말고** 준비부터 한다. 먼저 읽으면 서술에 끌려간다.

```bash
AUDIT="<audit.py 경로>"      # 예: .claude/scripts/audit/audit.py
python "$AUDIT" --help >/dev/null || echo "도구 경로를 확인할 것"
```

**원본 파일 목록을 사용자에게 확인받는다.** 이것이 이 작업의 성패를 가른다 —
원본이 덜 들어오면 멀쩡한 숫자가 「미발견」으로 쏟아지고, 그 속에 진짜 오류가 묻힌다.

물을 것 —

1. 보고서가 쓴 **원자료 파일**이 전부 어디에 있는가 (`.tsv` `.csv` `.xlsx` `.md` `.hwpx` `.hwp` `.pdf`)
2. 표 원본에서 **한 기관이 여러 행**으로 나뉘어 있는가 (본교/분교, 본원/지원)
   → 그렇다면 `--group <열>` 과 `--group-strip <접미사 정규식>` 을 쓴다
3. 보고서가 **전체가 아니라 일부만** 비교했는가 (예: 국공립 전체 중 거점국립대 9곳)
   → 그 부분집합만 담은 파일이 따로 있는지 묻는다. 없으면 `stat --filter` 로 재현한다

## 2. 숫자를 뽑고 한 번 돌려 본다

```bash
python "$AUDIT" claims <보고서.md> -o claims.json
python "$AUDIT" check claims.json --source <원본...> --group <열> --group-strip '<정규식>'
echo "종료코드 $?"
```

**이 단계의 목적은 지적이 아니라 잡음 줄이기다.** 「설명 필요」가 수십 건이면
원본이 덜 들어온 것이다. 사용자에게 **무엇이 더 필요한지** 말하고 받아서 다시 돌린다.

구형 `.hwp` 가 있으면 `--hwp-com --workdir <폴더>` 를 붙인다.
**한글 창이 열려 있으면 도구가 거부한다.** 사용자에게 닫아 달라고 하고 기다린다.

## 3. 정의 파일을 채운다 — 건너뛰지 않는다

```bash
python "$AUDIT" defs-template -o defs.json
```

보고서가 쓴 지표마다 **원문을 직접 열어** 채운다. 요약본·조사원 메모는 근거가 아니다.
**「원문」 칸이 비면 도구가 종료코드 5 로 막는다.**

파생지표(A÷B)가 있으면 **분자·분모를 각각** 등록한다. 이것이 이 감사의 핵심이다 —
5회차에서 값이 전부 맞는데 모집단이 달라 보고서 전체가 흔들렸다.

지표 정의를 못 찾으면 **지어내지 말고** 사용자에게 어디서 받을지 묻는다.

## 4. 감사역을 부른다

`report-auditor` 를 호출하고 **반드시** 넘긴다 —

- 보고서 경로 · 원본 파일 목록 · `defs.json` 경로
- 2단계에서 쓴 **명령 전문**(옵션 포함)과 종료코드
- 저장할 `검토의견_vN.md` 경로

감사역은 도구 출력을 **시작점**으로 쓰되, 지적할 값은 **원본을 열어 눈으로 확인**한다.

## 5. 결과를 사용자에게 올린다

치명·중대·경미 건수와 **「확인하지 못한 것」**을 함께 보고한다.
**원고는 고치지 않는다.** 고칠지 말지는 사용자가 정한다.

---

## 지켜야 할 것

- **「확인 못 함」은 「맞다」가 아니다.** 못 읽은 원본, 못 받은 정의, 재현 못 한 계산을
  §6 에 적는다. 조용히 넘기지 않는다
- **거짓 지적을 두려워한다.** 지적이 많으면 진짜가 묻힌다
- **도구는 판정하지 않는다.** 「다릅니다, 확인하십시오」까지가 도구의 일이고,
  판정은 감사역이, 결정은 사용자가 한다
- 개인정보(성명·생년월일·연락처)는 어느 산출물에도 넣지 않는다
- **불리한 숫자를 빼라고 하지 않는다.** 그건 편집이 아니라 조작이다
