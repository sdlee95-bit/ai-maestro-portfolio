# 부서 취합을 웹으로 — GAS 자동화 앱

**AI 마에스트로 6회차 과제** — GAS 자동화 앱 1개 배포
부산대학교 총무과 · 2026. 10.

부서에 **엑셀 서식을 뿌리고 회신을 모으던 일**을 주소 하나로 바꾼다.
입력이 들어오면 시트에 쌓이고, 담당자에게 메일이 가고, **누가 안 냈는지**가 현황판에 뜬다.

```
  부서 담당자                 Apps Script                 취합 담당자
  ──────────                 ───────────                 ──────────
  주소 하나 ──입력──▶  검증 → 시트 적재 → 알림 메일 ──▶  받은 메일에
                              │                           미제출 목록이 그대로
                              └──▶ 취합 현황판 ──────────▶ 안 낸 곳만 독촉
```

실제 대상 업무는 **「국립대학 비정규직(자체직원) 채용 현황 실태조사」**다.
아직 돌아가지 않은 조사라 **사전 연습**으로 만들었고, 전 구간을 가상 데이터로 검증했다.

---

## 왜 만들었나 — 취합에서 시간을 먹는 곳

서식을 돌려 모으는 일은 **입력이 오래 걸리는 게 아니다.**

| 단계 | 엑셀 서식 | 이 앱 |
|---|---|---|
| 배포 | 파일을 메일로 뿌린다 | **주소 하나** |
| 작성 | 서식을 열고 행을 채운다 | 웹 화면 |
| 연봉액 | **사람이 계산한다** | **자동** — `((A+B)×12)+C+D+E+F` |
| 담당자 정보 | **행마다 반복 입력** | **제출 1회당 한 번** |
| 무기계약직 종료일 | 적어 넣는 실수가 난다 | **입력 단계에서 막는다** |
| 취합 | 파일을 열어 붙여넣는다 | **이미 1건 = 1행으로 쌓여 있다** |
| **안 낸 곳 찾기** | **파일을 세어 본다** | **현황판에 바로 뜬다** |

맨 아랫줄이 핵심이다. 실무에서 가장 오래 걸리는 일은 입력이 아니라
**「누가 안 냈는지 찾아 독촉하는 일」**이다. 그래서 현황판을 따로 두었다.

알림 메일에도 **미제출 부서 이름을 전부** 넣었다. 취합 담당자는 현황판에 들어가지 않아도
**받은 메일 하나로 다음 할 일을 안다.** 제출이 들어올 때마다 그 목록이 저절로 줄어든다.

## 구성

```
06-gas-survey-app/
└── gas/
    ├── Code.gs       서버 — 설정·검증·적재·메일·집계
    ├── Index.html    입력 화면
    └── Status.html   취합 현황판
```

Apps Script 프로젝트에 같은 이름으로 넣고 **`setup` 을 한 번 실행**하면
스프레드시트가 자동으로 만들어진다. 그다음 **웹 앱으로 배포**하면 끝이다.

| 화면 | 주소 |
|---|---|
| 입력 | `.../exec` |
| 현황판 | `.../exec?page=status` |

## 서식이 바뀌면 배열 하나만 고친다

조사 서식은 해마다 바뀐다. 그래서 **입력 항목을 코드에 흩어 두지 않고 배열 하나로 모았다.**

```js
var FIELDS = [
  { key: '소속',            type: 'select', options: 'DEPTS', required: true },
  { key: '성명',            type: 'text',   required: true, pii: true },
  { key: '계약종료일',       type: 'date',   hint: '무기계약직은 비워 둡니다' },
  { key: '(A) 월급여(세전)', type: 'number', required: true, unit: '원' },
  { key: '연봉액',          type: 'number', calc: true },   // 서버가 계산
  ...
];
```

이 배열을 고치면 **입력 화면·시트 머리글·검증 규칙·현황판이 전부 따라온다.**
화면 HTML 을 손댈 필요가 없다 — 폼은 이 배열을 읽어 그려진다.

## 시행착오

### 1. 기관 계정에서 Apps Script 가 막혀 있었다

학교 Workspace 계정으로 들어가니 **「조직에서 이 서비스가 사용 중지되어 있습니다」**가 떴다.
Apps Script 뿐 아니라 **Google Docs 까지** 막혀 있었다. API 토글 문제가 아니라
**서비스 자체가 꺼진 계정**이었다.

→ 개인 계정으로 만들고, 기관 계정 사용 요청은 따로 올리기로 했다.
**Apps Script 는 코드가 계정에 묶이지 않는다.** 나중에 기관 계정이 열리면 코드만 옮기면 된다.

### 2. `clasp` 가 「인식되지 않습니다」로 계속 나왔다 — 범인은 실행 정책

CLI(`clasp`)로 배포하려 했는데 PowerShell 이 계속 명령을 못 찾았다.
전체 경로를 줘도 마찬가지였다. 진짜 원인은 파일이 없는 게 아니었다.

```
npm : 이 시스템에서 스크립트를 실행할 수 없으므로 npm.ps1 파일을 로드할 수 없습니다.
      UnauthorizedAccess / PSSecurityException
```

**PowerShell 실행 정책이 `.ps1` 을 막고 있었다.** `clasp` 를 치면 PowerShell 이
`clasp.ps1` 을 먼저 찾는데 그걸 못 읽어 **「없는 명령」처럼 보였다.**

- 보안 설정을 바꾸는 건 피했다. **`cmd` 로 실행하면 `.cmd` 를 쓰므로 이 제한을 안 받는다**
- 다만 이 과제에서는 **CLI 를 아예 버렸다.** 웹 편집기에 붙여넣고 배포해도
  **결과물(배포된 웹앱)은 완전히 같다.** CLI 는 편의일 뿐 필수가 아니다

### 3. 크로스오리진 iframe 이라 자동 검증이 막혔다

만든 화면을 자동으로 채워 제출까지 시험하려 했으나,
Apps Script 웹앱은 **다른 출처의 iframe** 안에서 돈다.
스크립트로 요소를 잡을 수 없고 화면 좌표로만 눌러야 하는데,
중간에 스크롤이 움직여 **글자가 엉뚱한 칸에 들어갔다.**

→ 자동 입력을 포기하고 **사람이 한 건 넣고, 결과를 눈으로 확인**했다.
읽기만 하는 **현황판은 자동으로 검증할 수 있었다.**

### 4. 쉼표가 없으면 0 이 하나 더 붙은 걸 못 잡는다

처음에는 시트에 숫자가 `30000000` 으로 들어갔다. 검토 과정에서 지적이 나왔다 —
**금액은 천 단위 쉼표가 있어야 눈으로 확인이 된다.**

같이 고친 것 둘.

- **제출일시에 시각이 없었다.** 날짜만 보이면 **「누가 언제 냈는지」**를 못 가린다
- **금액 빈칸을 공란으로 두었다.** 서식은 「포함된 경우 0 으로 작성」을 요구한다.
  공란과 0 은 제출 서식에 붙일 때 **다른 뜻으로 읽힌다**

값이 아니라 **표시 서식만** 바꿨다. 그리고 `setup` 은 시트를 비우므로,
**데이터가 있을 때 쓰는 `formatExisting`** 을 따로 두었다.

## 개인정보

이 서식은 **성명·생년월일**을 받는다. 그래서 —

- 입력 화면 맨 위에 **수집 목적과 파기 시점**을 띄운다
- **이 저장소에는 코드만 올린다.** 배포 주소도 넣지 않았다
- 전 과정을 **가상 데이터**로만 검증했다. 실제 직원 정보는 한 건도 들어가지 않았다
- 실제 업무에 쓸 때는 기관 계정에서 **접근 범위를 구성원으로 좁혀야 한다**

## 얻은 것

1. **시트가 곧 서버다.** 데이터베이스를 따로 세우지 않아도 취합 업무는 돌아간다.
2. **자동 계산과 입력 차단이 서식의 절반을 대신한다.** 사람이 틀릴 수 있는 칸을
   아예 못 틀리게 만드는 쪽이, 틀린 것을 나중에 잡는 쪽보다 싸다.
3. **취합의 병목은 입력이 아니라 추적이다.** 현황판과 알림 메일에
   **미제출 목록**을 넣은 것이 이 앱에서 가장 쓸모 있는 부분이다.
4. **도구가 막히면 도구를 버린다.** CLI 설치에 매달리지 않고 웹 편집기로 돌렸다.
   결과물은 같았고, 시간은 아꼈다.
