# 인력 재배치 리서치 — 조사부터 목차 확정까지

주제: **$ARGUMENTS**
(비어 있으면 「국립대학 지원정책 확대에 따른 부족인력 재배치 방안」으로 진행한다)

> **$1 이 아니라 $ARGUMENTS 를 쓴다.** $1 은 첫 낱말만 가져가서
> 「국립대학 지원정책 확대에 따른…」이 「국립대학」으로 잘린다.
> 1차 재실행 검증에서 실제로 「지원정책」 한 단어만 들어왔다.

아래를 순서대로 수행한다.

## 1. 준비 확인

```bash
agent-browser --version || npm i -g agent-browser && agent-browser install
```

없으면 전역(유저 스코프)으로 설치한다.

산출 폴더를 정한다 — 기본값
`<산출 폴더>`
이미 결과 md 가 있으면 **덮어쓰기 전에 사용자에게 알린다.**

## 2. 조사원 5명을 한 번에 띄운다

**반드시 한 메시지 안에서 Agent 호출 5개를 동시에 보낸다.** 순서대로 하나씩
기다리지 않는다. 각 조사원에게 15분 제한과 저장 경로를 명시한다.

| # | subagent_type | 담당 | 저장 파일 |
|---|---|---|---|
| 1 | `policy-researcher` | 교육부 | `01_정책_교육부.md` |
| 2 | `policy-researcher` | 부산광역시 | `01_정책_부산광역시.md` |
| 3 | `policy-researcher` | 한국연구재단 | `01_정책_한국연구재단.md` |
| 4 | `univ-researcher` | 타 대학 사례 | `02_타대학.md` |
| 5 | `pnu-researcher` | 부산대 현황 | `03_부산대.md` |

`pnu-researcher` 에게는 자료 폴더를 알려 준다 —
`<기관 자료 폴더>`
(**읽기만 할 것. 이 폴더의 파일을 수정·이동·삭제하지 않는다.**)

다섯이 모두 끝날 때까지 기다린다. 실패한 조사원이 있으면 **다시 돌리지 말고**
무엇이 안 됐는지 사용자에게 알린 뒤 지시를 기다린다.

## 3. 결과를 사용자에게 보고한다

조사원별로 **무엇을 얼마나 건졌는지, 무엇이 비었는지** 짧게 정리해 올린다.
파일 목록과 각 파일의 분량도 같이 보여 준다.

## 4. 편집장을 부른다

`report-editor` 를 호출해 결과 5개를 모두 읽히고
`04_목차_스토리라인.md` 를 짜게 한다.

## 5. 사용자와 목차를 확정한다 — 이 단계를 건너뛰지 않는다

편집장의 초안을 그대로 확정하지 않는다. 초안의 **「확정이 필요한 쟁점」**을 들고
사용자와 대화한다. 반드시 다음 셋을 함께 정한다.

1. **언급할 점** — 무엇을 보고서에 싣는가
2. **언급하되 가릴 점** — 사실이지만 표현 수위를 낮출 대목
3. **이야기 순서** — 어떤 순서로 설득할 것인가

쟁점은 **한 번에 하나씩** 올리고 답을 기다린다. 몰아서 묻지 않는다.
권고안은 분명히 제시하되, 결정은 사용자가 한다.

확정되면 `04_목차_스토리라인.md` 를 갱신하고 상태를 ✅ 확정으로 바꾼다.

## 지켜야 할 것

- **나중에 3장짜리 요약보고서를 따로 만든다.** 본보고서에서 그대로 잘라내면
  요약이 되도록 목차를 짠다.
- 개인정보(성명·생년월일·연락처)는 어느 산출물에도 넣지 않는다. 집계값만 쓴다.
- 원자료의 수치가 서로 어긋나면 **고치지 말고 그대로 드러낸다.**
- 조사원이 못 찾은 것은 「확인하지 못한 것」으로 남긴다. 채워 넣지 않는다.
