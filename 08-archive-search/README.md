## 왜 만들었나 — 제출이 끝이 아니었다

매년 제출하는 정원 요구 자료를 분석했더니 이렇게 나왔다.

| 단계 | 자료 |
|---|---|
| 요구서 작성·제출 | 117건 |
| **제출 이후 추가 요구 대응** | **522건 (82%)** |

상급기관이 **요구 건마다 따로** 자료를 요구한다. 그 작성 항목에 이런 게 있다.

> ○ 요구목록별로 1)요구명, 2)부서별 업무수행현황, 3)부서 정·현원,
> **4) 5년간 요구이력**, 5)부서별 업무분장 작성

**「5년간 요구이력」을 채우려면 과거 자료를 전부 뒤져야 한다.**
그 더미의 정체는 **9개년치 요구 이력 전체**였다.

| 2019 | 2020 | 2021 | 2022 | 2023 | 2024 | 2025 | 2026 | 2027 |
|---|---|---|---|---|---|---|---|---|
| 3 | 7 | 12 | 127 | 42 | 78 | 60 | 93 | 202 |

파일명만으로는 못 찾는다. 「작년에 이걸 어떻게 썼더라」는 **본문을 열어 봐야** 알 수 있고,
그 본문이 수백 개다.

## 구형 한글(.hwp)을 한글 없이 읽는다

이 저장소에서 가장 쓸모 있는 파일은 `tools/hwp_text.py` 하나일지 모른다.

종전에는 `.hwp` 를 읽으려면 **한글 프로그램을 COM으로 띄워야** 했다.
느리고, 사용자가 열어 둔 문서를 건드릴 위험이 있고, 창 없는 프로세스가 남는다.
**파일이 수백 개면 쓸 수 없는 방법이다.**

`.hwp` 5.0 은 **OLE 복합문서**다. 구조만 알면 파이썬으로 바로 읽힌다.

```
FileHeader           36번째 바이트 flags — bit0 이 켜져 있으면 본문이 압축돼 있다
BodyText/SectionN    압축돼 있으면 raw deflate (zlib.decompress(d, -15))
레코드 헤더 4바이트   tagID(10bit) | level(10bit) | size(12bit)
                     size 가 0xFFF 면 다음 4바이트가 진짜 크기
tagID 67             HWPTAG_PARA_TEXT — 본문 글자 (UTF-16LE)
```

**실측 325건 중 306건(94%)** 을 읽었다. 실패 0건.
못 읽은 19건은 **「상위 버전 배포용 문서」** — 본문이 잠겨 있다(같은 공문의 PDF로 대체된다).

### 걸린 함정 둘

**① 제어 문자가 섞여 있다.** 그냥 디코딩하면 깨진 기호가 쏟아진다.
0~31 중 inline·extended 제어는 **8워드(16바이트)를 차지**하므로 통째로 건너뛴다.

**② 서로게이트 쌍을 결합해야 한다.** UTF-16LE 라 한 글자가 두 워드에 걸치는 경우가 있는데,
그냥 `chr()` 로 넘기면 짝 없는 서로게이트가 남아 나중에 `encode("utf-8")` 이 터진다.
**색인 전체가 거기서 멈춘다.**

## 구성

```
08-archive-search/
└── tools/
    ├── hwp_text.py      구형 한글(.hwp)을 한글 프로그램 없이 판독
    ├── build_index.py   더미 전체를 색인 (hwp/hwpx/xlsx/pdf)
    ├── search.py        연도별 균형 검색 · 등장 추이 · 전문 보기
    ├── history.py       「N년간 이력」 표 자동 작성 (+ 보고서 서식 출력)
    ├── scan_hwp.py      판독률 실측 — 짐작으로 말하지 않기 위해
    └── hwpx2pdf.py      hwpx → hwp·pdf (쪽수 확인용, 한글 COM 사용)
```

```bash
python build_index.py <자료폴더> index.json
python search.py 전산 증원 --kind 요구서
python search.py --timeline 전산
python history.py 전산 증원 --hwpx 이력.hwpx
```

## 설계에서 고민한 것

### 1. 최신 연도가 결과를 다 먹으면 쓸모가 없다

처음 만들었을 때 검색 결과가 **가장 최근 연도로 가득 찼다.**
그런데 이 도구를 쓰는 이유가 **「작년엔 뭐라고 썼지」**다. 최신만 보여 주면 답을 못 한다.

→ **연도마다 상위 몇 건씩** 뽑도록 바꿨다.

### 2. 연도 판정을 바깥 폴더에서 하면 전부 한 해로 묶인다

처음엔 624건 중 **548건이 한 해로 몰렸다.** 바깥 폴더 이름을 먼저 읽었기 때문이다.
과거 자료가 전부 올해 폴더 안에 들어 있으니 당연한 결과였다.

→ **파일명 → 가장 안쪽 폴더 → 바깥 폴더** 순으로 고쳤다. 그제야 9개년이 갈렸다.

### 3. 같은 낱말이 다른 뜻으로 쓰인 해가 섞인다

「전산」으로 찾으면 **전산 인력 요구**가 아니라 업무 **전산화**를 말한 문서까지 걸린다.
실제로 시험 중에 두 해가 그렇게 섞였다. **그대로 믿으면 없는 이력을 적게 된다.**

→ 고치는 대신 **드러냈다.**

```
## 근거 문맥 — 반드시 읽고 거를 것
같은 낱말이 다른 뜻으로 쓰인 해가 섞인다. …
표를 그대로 옮기지 말고 위 문맥을 보고 해당 없는 해를 지울 것.
```

추출하지 못한 값은 **「원문 확인 필요」** 로 표시한다. 빈칸을 그럴듯하게 채우지 않는다.

### 4. 요구 「사유」는 쓰지 않는다

이 도구는 **「과거에 무엇을 요구했는가」라는 사실**만 모은다.
증원 사유나 논리는 담당자의 판단이고, 거기까지 넘기면 쓸 수 없는 문서가 나온다.

## 얻은 것

1. **한 겹을 걷어내면 다음 겹이 보인다.** 「요구서 작성을 돕자」로 시작했는데,
   자료를 세어 보니 **진짜 일은 제출 이후**에 있었다. 파일 수를 세는 것만으로 드러났다.
2. **제약이라고 믿던 것이 제약이 아닐 수 있다.** 「.hwp 는 한글을 띄워야 읽는다」를
   일곱 달 동안 전제로 삼았는데, 포맷을 들여다보니 100줄로 풀렸다.
3. **틀릴 수 있다는 것을 숨기면 더 위험하다.** 동음이의로 섞이는 문제를 없앨 수 없다면,
   **반드시 읽고 거르라고 크게 적는 것**이 답이다.
4. **검증은 자기 문서에도 해야 한다.** 이 과제의 검토 보고서를 쓰면서
   실측 결과를 다시 확인하지 않고 기억으로 숫자를 적었고, **네 군데가 틀렸다.**
   담당자가 잡아 주었다. 도구를 만든 사람도 예외가 아니다.
