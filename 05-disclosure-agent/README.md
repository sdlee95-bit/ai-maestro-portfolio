## 1. 화면 텍스트로 안 읽히는 사이트를 뚫었다

벽이 두 겹이었다.

| 벽 | 무엇 | 뚫는 법 |
|---|---|---|
| 1 | 공시항목 목록이 **RealGrid**(캔버스) | `dataProvider` 를 직접 읽는다 |
| 2 | 데이터 표가 **UBIReport 뷰어** | 뷰어 내부 함수로 쪽마다 그리게 한다 |

`fetch` 로 POST 해도 소용없다 — 돌아오는 HTML 은 제목만 있는 껍데기이고
본문은 뷰어가 따로 받아 그린다. **페이지를 실제로 띄워야 한다.**

도구로 뺐다 → [`tools/alimi.py`](tools/alimi.py) (브라우저에 넣을 JS 를 찍어 준다)

```bash
python tools/alimi.py open 2026 195 | agent-browser --session sd --args "--no-sandbox" eval --stdin
agent-browser --session sd --args "--no-sandbox" wait --load networkidle
python tools/alimi.py grab | agent-browser --session sd --args "--no-sandbox" eval --stdin > raw.json
python tools/alimi.py parse raw.json 직원현황_2026.tsv     # 불완전하면 exit 3
```

## 2. 쪽 번호를 믿었다가 틀릴 뻔했다 ← 가장 값진 실패

뷰어가 `scrollpage` 모드라 **보이는 쪽만 그린다.** 안 보이는 쪽은 DOM 에 아예 없다.

- `NextButton.click()` — 쪽 번호만 올라가고 내용은 그대로
- `gopage(n)` — 마찬가지

13쪽을 다 훑었다고 생각했는데 **13쪽 전부가 1쪽 내용**이었다.
스크롤하면 그려지긴 하는데, **창이 숨어 있으면 그것도 안 된다** —
`window.innerHeight === 0` 이라 `clientHeight === scrollHeight` 가 되어 스크롤이 성립하지 않는다.

→ 뷰어 내부 함수를 직접 부른다. 창 상태와 무관하다.

```js
v._createPreview(n);
v._requestReportPage(n);
```

그리고 **`complete` 플래그**를 결과에 넣고, **`parse` 가 불완전하면 종료코드 3** 을 내게 했다.
「불완전한 데이터는 쓰지 않는다」를 **글이 아니라 종료코드로 강제**한 것이다.
지침은 안 읽고 넘어갈 수 있지만 종료코드는 못 넘어간다. **이 장치가 실제로 사고를 잡았다.**

## 3. 열 개수를 상수로 박으면 조용히 틀린다

담당 항목의 세부 구분이 **특정 연도에 바뀌어** 숫자 열이 20개 → 16개가 됐다.
16으로 박고 옛 연도를 읽으면 값이 통째로 밀린다. 운 좋게 추출이 0건으로 나와서 알아챘다.
**밀린 채로 나왔으면 못 잡았다.**

→ 행 끝에서 이어지는 숫자의 길이를 세어 **최빈값으로 열 수를 정한다.**
머리글 줄도 그대로 돌려주어 그해 배치를 사람이 확인하게 한다.

## 4. 감사역을 붙였다 — 원본을 다시 여는 것부터 시킨다

앞 과제에서 담당자가 잡아 준 오류는 **전부 같은 경로**였다 — 원자료를 안 보고 요약·추측으로 쓴 것.
그래서 [`agents/disclosure-auditor.md`](agents/disclosure-auditor.md) 의 첫 번째 일은
보고서를 읽는 게 아니라 **원본을 다시 여는 것**이다.

- **독립 재수집** — 조사원과 **다른 브라우저 세션**으로 직접 다시 뽑아 행 단위 대조
- **정의 감사** — 조사원의 「말하면 안 되는 것」을 먼저 읽고, 보고서가 그 선을 넘었는지 본다
- 치명 / 중대 / 경미, **「어떻게 고치나」를 반드시 채운다**
- **3회 왕복 상한**, 3회차에 **남은 미해결 지적**을 별도 절로
- **원고 수정 권한 없음** — 지적과 수정을 갈라야 이력이 파일로 남는다

## 5. 실제로 감사가 잡은 것

3회 왕복에서 **치명 3 · 중대 10 · 경미 13**. 건수가 줄지 않았는데, 같은 곳을 다시 본 게 아니라
**새로 생긴 표면**을 본 것이다.

| 회차 | 치명 지적 |
|---|---|
| 1 | 「이 칸은 그해 사건을 적는다」는 **단정을 반증** — 같은 표시가 네 해 연속 붙어 있었다 |
| 2 | **개고가 만든 새 오류** — 구간 나누기의 경계가 그룹 내부 폭보다 좁았다 |
| 3 | **분자와 분모의 모집단이 달랐다** — 지침서를 세 줄만 대조하고 【공시기관】·【공시내용】을 건너뛴 탓 |

특히 1회차가 값졌다. **조사원이 `[추론]` 으로 남긴 것을 사람이 「사실」로 뒤집은 것**이었고,
감사역이 원표 네 해를 꺼내 되돌렸다. 조사원 판정을 검증하랬더니 반대로 격상시킨 셈이다.

3회차는 더 컸다. 2회차에서 「기준일 미확인」 방어막을 걷어낸 자리에
**더 큰 범위 문제를 「정확하다」로 덮어** 앞 판본보다 나쁜 상태였다.

## 6. 감사가 끝난 뒤 자료가 들어왔다

3회차가 **「세 회차 모두 열어 보지 않았다」**고 지적한 **개별 공시 원표**를 열었다.
전체 조회 화면은 회계 구분을 합쳐서만 주고, **학교를 지정해야** 갈린다.

받아 보니 **비교 결과의 순서가 하나도 바뀌지 않았다.**
한계가 사라진 것이 아니라 **결론의 근거가 하나 늘었다** — 「받아 봐야 안다」가 **「받아 봤고, 같다」**가 됐다.

## 함정 둘 더

**JS 를 파이프로 넘기면 한글 주석이 JS 를 죽인다.**
윈도우 콘솔이 cp949 라 주석이 깨지고, 깨진 바이트가 다음 줄까지 먹어 변수 선언이 사라진다.
`ReferenceError` 가 뜨는데 원인이 안 보인다. → `alimi.py` 안에서 stdout 을 UTF-8 로 못박았다.

**개고 이력이 보고서를 두 배로 만든다.**
판본마다 「왜 이렇게 썼는지」가 쌓여 결재본이 33쪽이 됐다.
개고 이력은 **작업 기록이지 보고 문서가 아니다.** [`tools/split_report.py`](tools/split_report.py) 로 가른다.
자를 때 **개고 이력 뒤에 있던 각주 정의를 본문으로 되돌려야** 한다 — 안 그러면 각주 참조가 전부 깨진다.

## 세 에이전트에 일부러 박아 둔 제약

| 에이전트 | 못 하게 한 것 |
|---|---|
| 조사원 | **판단하지 않는다.** 있고 없는 것만 적는다. 불완전한 데이터는 **종료코드로 막힌다** |
| 감사역 | **원고 수정 권한 없음.** 지적만 한다 |
| 편집자 | **쟁점을 혼자 정하지 않는다.** 그리고 **불리한 숫자를 뺄 수 없다** |

마지막 것이 이번 과제의 핵심이었다. 분석 결과가 **우리 대학에 유리하지 않게** 나왔는데
다섯 판본 내내 그대로 실었다.

> **불리한 숫자를 빼는 것은 편집이 아니라 조작이다.**
> 숫자는 그대로 싣고, 그 숫자가 왜 현장 체감과 다른지를 쓴다.
> 그래도 설명이 안 되면 **「설명되지 않는다」고 쓴다.**

원표 값은 첫 판본부터 마지막까지 **한 번도 바뀌지 않았다.**
다섯 판본이 고친 것은 전부 **그 값을 어떻게 읽었는가**였다.
