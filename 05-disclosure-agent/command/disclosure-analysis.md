# 부서 공시자료 분석 파이프라인

분석 대상: **$ARGUMENTS** *(비어 있으면 `총무과 직원 현황` 으로 진행)*

> `$1` 을 쓰면 첫 낱말만 들어온다. **반드시 `$ARGUMENTS` 를 쓸 것.**

대학알리미 공시자료에서 우리 부서 담당 지표를 뽑아, **감사역이 다시 대조한 뒤**
부서장에게 보여줄 1장 요약과 보고서를 만든다.

---

## STEP 0 — 준비 (조용히)

1. `agent-browser --version` 확인. 없으면 알리고 설치:
   `npm install -g agent-browser` → `agent-browser install`
2. 오늘 날짜로 산출 폴더를 만든다: `<작업폴더>\03.산출물\<YYYY-MM-DD>\`
   **기존 파일을 지우지 마라.** 같은 이름이면 덮어쓰되 다른 파일은 손대지 않는다
3. 도구 위치 확인: `.claude\scripts\alimi\alimi.py`
4. TaskCreate 로 진행 상황을 추적한다

> **환경 메모(검증됨)** — `--args "--no-sandbox"` 없이 실행하면 Chrome 이 즉시 죽는다.
> 모든 조사원·감사역에게 이 플래그를 전달할 것.

## STEP 1 — 담당 지표를 정한다

`.claude\scripts\alimi\부서별_공시항목.md` 에서 부서에 해당하는 항목을 찾는다.

- 후보가 여럿이면 **AskUserQuestion 으로 하나를 고르게 한다.** 임의로 정하지 마라
- 사전에 없는 부서면 `alimi.py items` 로 122건을 뽑아 후보를 추려 올린다
- 비교군(기본: 거점국립대 9곳 + 부산대)과 연도 범위(기본: 최근 5개 공시연도)를 확인한다

## STEP 2 — 조사원 실행

`disclosure-researcher` 를 호출한다. 항목이 둘 이상이면 **한 메시지에 담아 동시에** 보낸다.

각 프롬프트에 반드시 넣을 것 —

- 에이전트 정의 파일 경로(`.claude/agents/disclosure-researcher.md`)를 **가장 먼저 Read** 하라는 지시
- `{{ITEM_ID}}` `{{ITEM_NAME}}` `{{YEARS}}` `{{PEERS}}` `{{OUTPUT_PATH}}` `{{SESSION_ID}}`
- `alimi.py` 의 절대 경로
- 조사원마다 **다른 `{{SESSION_ID}}`** (`sd-a`, `sd-b` …)
- **20분 제한**, 16분에 수집 중단

> `subagent_type` 이 `not found` 면 그 세션에 정의가 아직 안 실린 것이다.
> `general-purpose` 로 바꾸고 프롬프트 첫 줄에서 정의 파일을 Read 하게 하면 똑같이 돈다.

끝나면 **연도별 `complete` 가 전부 `true` 인지 직접 확인한다.**
하나라도 `false` 면 그 연도는 다시 돌린다. **`false` 인 채로 다음 단계로 넘어가지 마라.**

## STEP 3 — 결과 보고

조사원별로 무엇을 건졌고 무엇이 비었는지 짧게 올린다.
**지표 정의(§0)를 찾았는지**와 **§6에 무엇이 적혔는지**를 반드시 포함한다.

## STEP 4 — 편집자 초안 (`draft`)

`disclosure-writer` 를 `draft` 모드로 호출해 **확정이 필요한 쟁점**을 뽑게 한다.

## STEP 5 — 사람과 확정한다 ← 건너뛰지 않는다

쟁점을 **한 번에 하나씩** 올리고 답을 기다린다. 몰아서 묻지 않는다.
최소한 이 셋은 반드시 정한다.

1. **언급할 점** — 무엇을 싣는가
2. **언급하되 가릴 점** — 사실이지만 표현 수위를 낮출 대목
3. **이야기 순서**

권고는 분명히 내되 결정은 사람이 한다.
**우리에게 불리한 숫자를 빼자는 제안은 하지 마라.** 싣되 설명하는 쪽으로 선택지를 짠다.

## STEP 6 — 집필 → 감사 → 개고 (3회 왕복)

```
v1 → 감사 → v2 → 감사 → v3 → 감사 → v4
```

- `disclosure-writer` `write` → `보고서_v1.md` + `1장요약_v1.md`
- `disclosure-auditor` → `검토의견_v1.md`
  **감사역은 원본에서 직접 다시 뽑아 대조한다.** 조사원 tsv 를 믿지 않는다.
  세션 이름을 조사원과 다르게 준다(`au-a`)
- `disclosure-writer` `revise` → `보고서_v2.md` + 개고 이력
- **3회를 채운다.** 지적이 0건이어도, 줄지 않아도 조기 종료하지 않는다
- 3회차 검토의견에는 **남은 미해결 지적**이 별도 절로 들어가야 한다

## STEP 7 — 마감

1. `버전비교.md` — v1~v4 가 무엇이 달라졌는지
2. 한글이 필요하면 `md2hwp.py` 로 변환하고 **PDF 를 떠서 쪽수를 눈으로 확인**한다
3. 최종 보고 — 산출물 목록 · **남은 미해결 지적** · **사람이 확인해야 할 것**

## 지켜야 할 것

- **`complete: false` 인 데이터는 쓰지 않는다.** 쪽 번호 표시를 믿지 마라
- **열 위치를 상수로 박지 않는다.** 연도마다 바뀐다
- 조사원이 `미확인` 이라 한 것은 끝까지 `미확인` 이다. 추정으로 메우지 않는다
- 공시 수치와 내부 수치는 **범위와 기준일이 다르다.** 붙이려면 차이를 칸마다 밝힌다
- 개인정보는 어느 산출물에도 넣지 않는다. 집계값만 쓴다
- 원자료의 수치가 서로 어긋나면 **고치지 말고 그대로 드러낸다**
